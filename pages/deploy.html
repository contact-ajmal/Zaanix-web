Deploy

One container on a laptop. A cluster for the team.

ZAANIX is a single Node.js server with DuckDB inside it — nothing else to install. The image is multi-arch (amd64 and arm64) and ships with DuckDB's extensions, so it needs no network at runtime. It is available on request: talk to us for access and the deployment files.

Docker Compose

A docker-compose.yml, shared with access, runs ZAANIX and, by profile, what you want next to it.

ProfilesPostgreSQL metadata, ZAANIX Agent on :4300, Ollama for a local model, and Prometheus on :9090 — each switched on when you want it.
SecretsAn .env file holds the secrets and the first admin's credentials.
Data./data is mounted at /data; DuckDB spills to a tmpfs.
MemoryZAANIX_MEMORY caps the container (default 8g); DUCKDB_MEMORY_LIMIT caps the engines.

With ZAANIX Agent

The agent is its own server and web app on :4300. It signs people in through ZAANIX and keeps its missions in its own store.

The agent guide 
# .env — a model for everyone; leave it out and people bring their own key
# provider: anthropic | openai | openrouter | ollama | openai-compatible
AGENT_MODEL_PROVIDER=anthropic
AGENT_MODEL=claude-sonnet-5
AGENT_MODEL_API_KEY=sk-ant-…
Where it finds ZAANIXZAANIX_URL (server to server) and ZAANIX_PUBLIC_URL (for people's browsers, for "Open in ZAANIX").
Its own secretAGENT_SECRET signs its cookies and encrypts the ZAANIX credentials it keeps; generated if unset.
How far a request goesAGENT_MAX_STEPS, AGENT_MAX_RETRIES and AGENT_MAX_OUTPUT_TOKENS.
For a teamThe agent server is one client to ZAANIX; raise ZAANIX's per-client rate limit, for example ZAANIX__server__rate_limit_per_minute=6000.

Kubernetes and clusters

Kustomize manifests, shared with access, and a cluster mode for more than one node.

Deployment guide
Hardened by defaultLiveness, readiness and startup probes; non-root with a read-only root filesystem; a spill volume and a PVC for /data.
Cluster modeNodes share PostgreSQL metadata and a ReadWriteMany data volume. Each workspace's engine lives on one node; the others forward to it.
Scheduled work, onceSyncs, alerts, snapshots, checks and streams are claimed by exactly one node, and move when a node stops.
Sticky where it mattersData apps and MCP SSE sessions stay on their node (ClientIP affinity); everything else can go to any node.

MCP clients

Point Claude, Claude Code or Cursor at a running ZAANIX with a token that has the mcp scope.

MCP and agents 
claude mcp add --transport http zaanix http://localhost:4200/mcp \
  --header "Authorization: Bearer zx_…"

# or over stdio
zaanix mcp --token zx_… [--workspace <id>]

Configuration

Everything is in zaanix.config.yaml, and any key can be overridden with ZAANIX__SECTION__KEY. These cover most deployments.

All settings
VariableWhat it doesDefault
JWT_SECRETSigns sign-in sessions (16 characters or more). Required in production.generated per start
ENCRYPTION_KEY32-byte hex key for the credential vault (AES-256-GCM). Required in production.generated per start
ZAANIX_ADMIN_EMAIL, _PASSWORDThe first admin, created only when there are no users.none
ZAANIX_DATA_DIRThe folder every DuckDB read and write is confined to./data in the image
ZAANIX_FILESYSTEM_MODEfull for a personal machine; sandboxed for shared deployments.full
DATABASE_URLThe metadata store, sqlite://… or postgres://…. Migrations run at start.SQLite
ZAANIX_ENABLE_EXTERNAL_ACCESSLets a sandboxed deployment read s3://, gcs:// and https:// sources.false
DUCKDB_MEMORY_LIMIT, DUCKDB_THREADSThe engine's memory ceiling and threads.80%, auto
AUTH_STRATEGY and OIDC_*Single sign-on; OIDC_GROUPS_CLAIM maps identity-provider groups to teams.local
COPILOT_PROVIDER and keysThe server's AI: anthropic, openai, ollama, bedrock, bedrock_agent, agentcore.none
Upgrading. Metadata migrations are additive and run at start. Back up /app/meta (or your PostgreSQL database) before a major upgrade; the data directory is not touched.
